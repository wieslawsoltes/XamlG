# Upstream validation

The revision pins are in `tests/Upstream.props`. Production packages have **no dependency on XamlX**.

## Two distinct suites

`XamlG.XamlX.Baseline.Tests` runs the pinned upstream SRE/IL compiler and all 222 test cases available in that build configuration. The only harness adjustment is locating the runtime interfaces inside the combined test-reference assembly. This is the baseline, not a test of XamlG.

`XamlG.XamlX.Compatibility.Tests` routes compilation through XamlG syntax, Roslyn binding, typed C# emission and Roslyn assembly emission. It runs 217 upstream runtime/diagnostic cases: 198 linked test cases and 19 dynamic-setter cases. Test bodies and assertions are retained. A test-only source generator replaces the IL-specific dynamic-setter configuration with the public XamlG setter-provider extension point. Exception categories and legacy diagnostic IDs are translated at the harness boundary.

Five baseline cases are not counted as XamlG compatibility tests: four `ParserTests` cases assert XamlX's internal AST representation; `Dynamic_Setter_For_Public_Property_Should_Be_Shared` asserts an IL-only helper metadata name. C# output has different internal types and helper identifiers. These exclusions are explicit, not silently skipped successes.

The suites do not cover every custom transformer used by every XAML framework. In particular, passing the portable XamlX tests does not establish full Avalonia styling, selector or compiled-binding compatibility.

## Implementation audit beyond the pinned tests

Compare behavior against the pinned source as well as its tests. Native compiler regressions cover implementation details. The two upstream harnesses also link 222 additional cases from `tests/XamlG.XamlX.ParityCases` to execute identical assertions through both compilers. These authored differential tests use the `ParityRegression` category and separate TRX files; they do not increase the count of unmodified upstream assertions.

Shared regressions verify that static adders read the getter for every item before its value, while runtime alternatives evaluate the key and value first and read the getter only for a matching adder. |

| Runtime string conversions | `ValueBinder.TryConvert` binds nonliteral strings through the selected `Parse` method or a typed converter expression. | Explicit string-element whitespace | `ContentWhitespaceNormalizer` normalizes string elements while retaining their runtime conversion path. Twenty-one shared `StringElementWhitespaceTests` cases cover scalar values, converted values, `xml:space`, whitespace-significant getter collections and direct collection content. Keyed strings keep their existing directive-wrapped behavior. |
| Enum literal conversions | `ValueBinder` resolves exact field names, splits and trims names only for flags enums, and normalizes signed 64-bit numeric input to the underlying bits before C# emission. Property converters take precedence; a type converter remains available when the intrinsic conversion fails. Shared `EnumConversionTests` adds 76 cases for all eight underlying types, numeric wrapping, nullable values, flag combinations, invalid text, property/constructor values and converter precedence. |
| Member-specific text conversions | Property elements, attached getters and constructor arguments retain conversion metadata. String elements and `x:Arguments` preserve their namespace scopes. Static `Parse` takes precedence over type-level converters, while member converters override it. `TextConversionContextTests` executes these paths. |
| Framework-supplied converter metadata | `IXamlTypeConverterProvider` resolves converter symbols through the shared literal, runtime-value and type-probing paths. Providers precede declared type attributes; member converters and `Parse` retain their existing priority. Seven native `TypeConverterProviderTests` cases verify precedence, runtime inputs, converter validation and absence of application-code execution during binding. |
| Intrinsic value-type probing | `ValueTypeProbe` shares intrinsic normalization and static-member resolution with binding. Shared `IntrinsicValueTests` covers typed static values, collection replacement and constructor selection. Native `IntrinsicTypeProbeTests` covers arrays, known and forward references, and diagnostics. `x:Array`, `x:Reference` and property-element namespace declarations extend beyond the pinned upstream parser/intrinsics and are tested natively. |
| Intrinsic object/property-element forms | `IntrinsicMarkupBinder` supports `TypeName`, `Member` and `Name` property elements, preserves generic-argument namespace scopes, and diagnoses duplicate/unknown arguments. `IntrinsicObjectTests` covers these forms, forward references, Boolean collection values and framework rule overrides. |
| Inherited content and qualified members | `MemberBinder` retains the metadata-selected content property and resolves qualified properties/events on their stated owner. Emission qualifies receivers when a derived member hides that symbol. Shared `InheritedMemberTests` covers scalar content, attributes/property elements, static/runtime collection getters, collection replacement and event adders. |
| Inherited metadata | `RoslynTypeSystem` explicitly inherits whitespace and initialization metadata, with the nearest initialization flag taking precedence. Converter attributes remain attached to their declaring type/property. Shared `InheritedMetadataTests` covers derived whitespace collections, trimming, initialization overrides, type-converter noninheritance and selected virtual-property converters. |
| Converted reference objects | The portable `XamlTextObjectExpressionRule` uses `Parse` and type converters for text bodies, string elements and string-valued markup children; shared `ObjectConversionTests` executes these forms. These roots are therefore not claimed as an upstream-supported missing feature. |

The pinned framework-transform comparison is recorded in [the complete transform inventory](avalonia-transform-audit.md). It maps all 38 registered Avalonia document transforms and both group transforms to native implementation and executable evidence. This is a source-surface completion review, not a claim that finite tests cover every possible XAML program. Existing native extensions and upstream limitations remain explicit.

The native Avalonia suite now also references the pinned `Avalonia.Markup.Xaml.Loader` 12.1.3 package solely for differential tests. `ContainerQueryTests` compares compiled query construction, invalid-input rejection and named-container layout behavior against that compiler. Production projects retain no XamlX or runtime-XAML-loader dependency. The query parser and binder emit typed public `StyleQueries` calls and preserve the pinned compiled transform's height/conjunction behavior, which differs from Avalonia's reflection query parser.

`TemplatePartTests` compares missing/incorrect part diagnostics, inherited and overridden declarations, explicit/inferred target types and nested/outer namescope isolation against the same package. `BoundDeferredExpression.NameScopeId` retains the scope allocated by binding, and the name registry preserves declaration spans for those diagnostics.

`StyleScopeTests` compares derived styles/themes, custom template scopes declared through an interface, object-form and qualified target properties, selectorless owning-control inference, invalid theme scopes and `x:SetterTargetType` precedence against the same compiler. Template property references use those semantic scopes when resolving `TemplateBinding` values.

`SetterContractTests` adds 104 differential cases for required style scopes, literal property forms, property-name grammar, CLR versus qualified registration types, ignored member converters, explicit setter targets and class setters. Template scopes do not replace the nearest style scope, and unknown style targets stop lookup. Unqualified properties use the CLR declaration, including an untyped registration, with fallback to attached accessors declared on the target. Cases cover getter/setter type precedence, read-only and write-only accessors, events and inherited registration boundaries. Qualified properties require a typed registration. Property-element text is consumed before whitespace normalization. Class references emit the public `GetClassProperty` call, preserve the pinned activator restrictions and remain invalid as compiled attached-property paths. Live checks verify class binding updates and self bindings under explicit setter targets. A native case preserves property-element namespace declarations, which extend the pinned parser.

`SelectorContractTests` adds 35 differential cases for selector value forms, CLR and attached-property contracts, literal property values, nesting order, escapes and traversal. Selector properties require one text node before general content normalization; empty attributes and whitespace text retain selectorless behavior. Ordinary property selectors use the CLR value type and its declaring registration, ignoring property-level converters; attached selectors require a preceding target type and an `AttachedProperty` registration. Quotes, whitespace and markup-looking property values remain literal. Runtime checks verify actual style application, including hidden registrations and differing CLR/registration value types. Trailing/repeated child traversals and nesting positions accepted by the pinned compiler are retained; incomplete template traversal keeps its runtime validation failure. Three native cases preserve XamlG's property-element namespaces and whitespace tolerance, which extend the pinned parser.

`StyleWarningTests` adds 30 differential cases for duplicate setters, item containers in data templates and styles in merged dictionaries. These check warning severity/count, negative scopes, successful construction and Avalonia's runtime duplicate-setter exception. The implementation preserves observed upstream restrictions: duplicate detection compares direct-content literal property names; container warnings require a `ContentControl`; target-type metadata wrappers suppress the immediate-parent merged-dictionary check.

`TemplatePriorityTests` adds 16 differential cases covering explicit styled/attached properties, CLR-wrapper bypass, style-trigger overrides, custom template scopes, literal/static/dynamic resources, binding priorities, direct properties, implicit/explicit content and assigned binding values. A native live-edit check also verifies source declarations and the generated setter. `BoundStaticSetter` supplies typed method/descriptor symbols without adding Avalonia names to the portable backend; `BoundMember.IsImplicitContent` preserves the pinned compiler's different handling of implicit content.

`DataTypeMetadataTests` adds 18 differential cases for `x:DataType`, annotated CLR properties, template matching and compiled template bodies. The directive assigns an annotated `DataType` property unless that property was explicitly assigned; in that case the directive still takes precedence for binding scope. Symbol-based member binding retains an inherited annotated property even when an unannotated derived property hides it. All `IDataTemplate` implementations establish a separate data-context type scope, and custom `[DataType]` properties support attribute and property-element values.

`DataContextInferenceTests` adds 21 differential cases for compiled `DataContext` results, property order, nested controls, arrays, reflection boundaries and explicit scope overrides. Binding results are retained during scope inference and reused for assignment, including failed results, so sources are constructed once and diagnostics are not duplicated. The pinned compiler resolves these paths from inherited metadata before the general binding `DataType`/`Source` transform; the tests preserve that precedence and validate ignored type names. A separate native check retains XamlG's existing inference from ordinary object-valued `DataContext` property elements, which extends the pinned compiler.

`ItemTypeInferenceTests` adds 35 differential cases for `[InheritDataTypeFromItems]`: standard/custom templates, assigned display bindings, arrays and generic enumerable interfaces, constructed/static/provided collections, nested item scopes and custom ancestor-selected column properties. `XamlPropertyBindingScope` exposes the owning property to framework rules and restores it after nested binding. Inference reuses cached typed paths in the source owner's object/property scope; dependency discovery preserves Avalonia's inference-before-binding-metadata order even when the collection assignment precedes its consumer. Explicit template types bypass that inference, reflection and non-generic sources cannot supply an item type, and a missing data-context declaration differs from metadata with an unknown type. Runtime checks verify updates and single source/provider construction.

`RegisteredSpecialValueTests` adds 26 differential cases for writable registered properties: static/provided unset values, attached and direct properties, assigned binding values, object-form providers, typed string conversions and style setter values. Runtime alternatives evaluate a provider once; a statically selected unset setter validates its provider but omits its construction and invocation, matching the pinned compiler. Template-priority alternatives drop the unset setter where a compatible priority setter exists. Style setters retain provided values without converting them to the registered property's type; only literal text takes that conversion path.

`RegisteredPropertySelectionTests` adds 29 differential cases for read-only wrappers, implicit content and qualified registrations. Read-only properties retain only the binding/unset alternatives available in the pinned transform; an object-valued provider on a read-only `[AssignBinding]` property selects the sole unset setter without evaluation. Template binding alternatives reject runtime unset/null values with the same exception categories. Implicit content uses the original CLR assignment, preserving provider evaluation and binding objects as values. Qualified base properties use their declaring registration even when a derived property hides it. A separate native regression extends XamlG's existing public-registration fallback to typed string conversion when no CLR setter is available.

`NamedBindingSourceTests` adds 40 differential cases for literal names, forward references, inferred data-context types and template boundaries. Qualified/property-element `Name` values and custom `INamed` objects register sources. A lazy catalog tracks deferred-property scopes and preserves the pinned compiler's document-scope precedence over template scopes. Named-source metadata stops at the selected scope boundary; data-context and item inference see only metadata preceding their consumer, while ordinary binding paths can use later declarations. Inline item bindings can use metadata on their owning object. Forward inference shares bound values and failed results with normal binding, preserving single source construction and diagnostics. A collection-metadata case also verifies that CLR property descriptors use their declaring type without inherited-indexer ambiguity.

`ProvidedNameTests` adds 31 differential cases for typed and object-valued providers, static members, string elements, null values, duplicate names, init-only setters and declaring-type boundaries. `BoundSetAssignment.RegisterName` retains the original string value, evaluates it once and registers it after the setter succeeds. Only statically string-valued assignments on properties declared by `INamed` implementations register names; runtime providers do not declare compiled-binding sources. Literal string elements do declare sources. Template instances and deferred resources register dynamic names in child scopes. A native regression preserves XamlG's existing support for struct objects, which the pinned compiler rejects outside converters.

`LiteralNameContractTests` adds 64 differential cases for unrestricted runtime name strings, forward sources, `x:Name` providers, declaring-type checks, assignment order, multiple aliases, duplicate-name timing and explicit string whitespace. `XamlFrameworkProfile.NameDirectiveProperty` maps the directive to an ordinary property assignment in source order. Names are registered after each string-valued setter; registering the same object twice succeeds, while different objects retain Avalonia's runtime exception. Compiled source metadata retains the first declaration. Five native cases preserve empty string elements and verify that code-behind emits fields only for valid C# names, including both valid aliases without changing runtime namescope keys.

`DeferredResourceTests` adds 18 differential cases for lazy reference resources, shared lookup results, eager strings/value types, literal names, names inside templates, null-producing providers, forward static-resource lookup, captured parent stacks and `x:Shared` validation. The pinned transform consumes both `x:Shared="True"` and `x:Shared="False"` as non-shared resources; tests preserve that observed behavior. Avalonia's public deferred-content factory supplies resource ancestry, child namescopes and sharing. A runtime adapter retains construction services and links constructed resource sessions to their owner. Four native cases preserve keyed null values, compiled resource-merge overrides and outer `x:Reference` resolution; existing inherited-resource tests cover supplied services and cleanup after construction failure. Resource preallocation is covered by `RemainingResourceTests`.

`RuntimeSourceInfoTests` adds 30 differential cases for opt-in Avalonia source metadata: construction/initialization timing, existing-root population, XML line endings, object and attribute markup extensions, deferred templates/resources, primitive and converted resource locations, getter/key evaluation order and failed insertion. Resource locations are recorded before lazy values are realized. Eager resource calls use the same static dictionary adder with metadata enabled or disabled. The portable runtime profile describes the metadata constructor/setter, and typed assignment post-calls reuse evaluated targets and arguments. Thirteen native cases cover compiled merges and overrides, code-behind factory timing, metadata surviving session disposal, unknown document paths and existing intrinsic/factory extensions rejected by the pinned compiler. Seven configuration cases cover Debug defaults and explicit host overrides. The capacity, deferred-resource and group-merge paths are included in the transform inventory.

`LiteralConstructionTests` adds 95 differential cases for fresh immutable brush literals, color grammar, URI/cursor/grid/row/column construction, TimeSpan shorthand, resource and property-text locations, converter allocation and metadata timing, invalid literals, and disabled metadata. Explicit string objects retain runtime parsing instead of intrinsic literal lowering. Whitespace-only scalar attributes preserve the pinned compiler's omission of setters/converters while string/object attributes retain their values. Incompatible immutable literals assigned to concrete mutable brush properties produce binding diagnostics. Font-family and row-definition collections retain the pinned absence of construction metadata.

`StructuredLiteralTests` adds 74 differential cases for thickness, point/vector/size, matrix, corner-radius and relative-point constants, static trimming/decoration/transparency/theme values, invalid inputs and resource locations. Numeric components preserve signed zero, non-finite values, optional-token consumption and the pinned intrinsic's affine-only matrix lowering; explicit string-object conversion retains runtime perspective. `ListLiteralTests` adds 44 differential cases for arrays, interface lists and concrete/derived Avalonia lists, inherited/null separators, split flags, coordinate pairs, item assignability, capacity and evaluation order, suppressed construction metadata and deferred resource locations. Empty collection attributes now preserve the existing property value; whitespace-separated numeric lists require declared separator metadata. Unsupported intrinsic item conversions can fall through to an available runtime list converter; malformed primitive items retain binding diagnostics. Deferred converter-list cases use the valid resource path: the pinned emitter rejects the same embedded converter under an ordinary property initializer because its parent-stack cache does not traverse the custom list node. Two native `ArrayEvaluationTests` regressions cover sequential provider evaluation and jagged-array allocation.

`EnumLiteralTests` adds 22 Avalonia differential cases for enum literals in registered properties, style setters, property selectors and boxed resources. Live controls verify that matching and style application use the converted enum values. The framework paths retain the portable binder's exact casing, flags requirement and signed 64-bit numeric grammar, including truncation to the enum's underlying width.

`SyntheticConverterTests` adds 67 differential cases for the pinned compiler's synthetic converter mappings: image/bitmap/image-brush sources, icons, cultures, URIs, point lists and generic Avalonia lists, with TimeSpan/font-family parser precedence. Tests cover literals, provided strings, exact target-type matching, member overrides, runtime failures, resource locations and nested constructor arguments. Image cases use headless bitmap/icon implementations and a scoped asset loader to verify URI routing and document base URIs. Runtime list tokenization retains converter behavior; runtime relative-font parsing retains the public parser's absent base URI. The constructor case uses a nested object because the pinned emitter cannot supply converter services before constructing the root.

`BindingPathMetadataTests` adds 23 differential cases for data-context metadata and registered binding sources. Inferred metadata applies only to `StyledElement.DataContextProperty` immediately after a named source or `$parent`; intermediate properties, casts, indexers, streams and attached-property syntax do not carry it forward. Self and visual-ancestor sources require explicit casts for typed data contexts. Registered properties supply their own result type and write access independently of CLR wrappers, including absent, differently typed, read-only and hidden wrappers. Runtime assertions verify updates and two-way writes. A native navigation check preserves CLR-property symbols where wrappers exist and registered-field symbols otherwise.

The pinned compiler's parser produces a `LogicalAncestorBindingExpressionNode` for `RelativeSource Tree=Logical`, but its path transformer does not handle that node. XamlG retains its existing implementation of logical relative sources. A separate native regression verifies ancestor data-context metadata and live updates for this extension; the same document is rejected by the pinned compiler. Existing native tree-selection tests cover ordinary logical and visual ancestor properties.


`DirectiveContractTests` covers runtime-discarded directives, parse errors, precompilation opt-outs, class/field visibility, skipped-file identity and tooling/cache recovery. `DirectiveIntegrationTests` and analyzer cases cover static, dynamic, inherited and URI loader opt-outs, expression trees, delegates and reordered named arguments. A separate pinned Avalonia MSBuild probe also verifies retained raw assets and public/internal compiled factories.

`RemainingScopeTests` compares implicit/typed ancestor selection, metadata boundaries and detached setter templates, including live template-binding updates. `RemainingBindingTests` executes method-valued delegates, command overload precedence, object-valued CanExecute predicates and dependency notifications, null-conditional paths and leading stream expressions. `RemainingTransformTests` compares animation/transition scopes, repeated option branches/defaults and predicate overload order. `RemainingResourceTests` compares capacity getter timing and init-only list capacity setters. Nineteen shared `PrimitiveConversionTests` cover CLR Boolean/float grammar and decimal runtime conversion/failure timing through both compilers.

## Run

```sh
git clone https://github.com/AvaloniaUI/XamlX external/XamlX
git -C external/XamlX checkout 7ef6aef496ab6e8dcf3df04bef697be49db37c04
dotnet test tests/XamlG.XamlX.Baseline.Tests -c Release --filter 'Category!=ParityRegression'
dotnet test tests/XamlG.XamlX.Compatibility.Tests -c Release --filter 'Category!=ParityRegression'
dotnet test tests/XamlG.XamlX.Baseline.Tests -c Release --no-build --filter Category=ParityRegression
dotnet test tests/XamlG.XamlX.Compatibility.Tests -c Release --no-build --filter Category=ParityRegression
```

The CI workflow retrieves the revision from the same props file and runs the two suites in separate jobs. TRX results distinguish the baseline from the replacement compiler.

Local evidence and compiler/upstream provenance are under `artifacts/tests/3e13368/`.

The same compiler checkpoint passed 1,507 native tests, 217 upstream compatibility tests and all 203 shared parity cases through XamlG, with no skipped tests and warning-free solution, compatibility, baseline and theme-runner builds. The original XamlX baseline also passed its 222 tests and all 203 shared parity cases at this checkpoint. TRX evidence for both compilers is under `artifacts/tests/literal-names/validation/`. This validates the executed cases, not subsequent compiler changes or the full framework transform surface.
